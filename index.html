项目概述

「影迹」是一款面向个人使用的 Android 影视记录与智能观影应用。原介绍页把它描述成影视兴趣、应用开发与 AI 产品探索放在一起的个人项目。

原介绍页称：观影记录、观影习惯记录，以及基于观影习惯的影视作品推荐都已可用，体验仍在继续完善。这些完成度是原作者对应用的说明，不是呆胶布的开发结论。

为什么做影迹

原介绍页写道：有些人看电影、剧时不方便记下观影记录和习惯，也希望按自己的习惯得到推荐。影迹把记录和推荐放进同一款应用。

目前可用的核心功能

以下三项是原介绍页列出的已可用能力：

  • 观影记录：记录观看过的影视作品。
  • 观影习惯：记录个人观影习惯。
  • 影视推荐：根据观影习惯推荐影视作品。

基础记录能力

  • 作品管理：管理个人影视记录。原 README 补充了新增、编辑、评分、观看进度与历史；分类必选，标签可选。
  • 分类与标签：用分类和标签整理作品，并可按它们浏览。
  • 观看状态：记录作品的观看状态。原 README 还提到想看、观看中和已看完。

原 README 另列了组合搜索、列表与海报墙、本地或在线海报、统计，以及加密 .yjb 备份。备份入口、密码规则和恢复限制以原仓库说明为准。本站不提供备份文件，也不收集观影数据。

AI 观影推荐

原介绍页称，基于观影习惯的影视推荐已经可用，项目接入了 DeepSeek API，并继续用个人观影记录和偏好整理观影画像。

本介绍页没有配置模型，没有发起任何 API 请求，也没有展示呆胶布自己的调用结果。

推荐如何形成

原介绍页把推荐拆成四步。这里按该页的说明转述，方便对照，不是本站重新实现的流程：

  1. 1
    准备候选 通过资料网关读取 TMDB 电影、剧集候选，并核对对应详情。
  2. 2
    确认偏好摘要 个性化推荐前，先向用户展示这次要用的画像摘要，确认后再发起模型请求。
  3. 3
    理解推荐方向 DeepSeek 根据偏好摘要给出主题方向和筛选条件。
  4. 4
    筛选与排序 应用依据候选资料、偏好和条件，在本地完成筛选与排序。

原介绍页强调：作品名称和详情来自影视资料源，模型输出限定为推荐方向与条件。

产品定位

原介绍页的定位是个人使用优先，重视本地使用和成本控制，不以多用户商业化为第一目标。

开发中遇到的难点

原介绍页把难点概括为：让推荐对上可以核对的真实影视资料，并处理资料链路里的网络和异常。

该页目前的做法是：作品资料用 TMDB；应用通过独立资料网关读取候选、详情和海报，再核对作品信息。DeepSeek 提供偏好方向和筛选条件，应用再在本地筛选、排序。

资料、模型建议和本地排序是分开的。没有有效候选时保留空结果；资料请求失败时给出错误反馈。资料源接入仍在完善。原开发记录里出现过上游直连受限，以及经代理完成本机只读验证的过程。这些是原项目文档里的经历，本站没有复现那次网络验证。
